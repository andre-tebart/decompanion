# Address comments: guard against interpretive claims without evidence

- **Source:** match-base session 2026-11-02 (gildegold), worker 36
- **Area:** dcp-match-base skill / Q6
- **Problem:** Q6 accepts any descriptive address comment. The worker nearly wrote guesses as facts ("town treasury", "rents rooms" - the latter already in the original comment) and caught them itself.
- **Proposal:** a skill line (or optional check) flagging interpretive nouns in an address comment that no string, caller or registration name backs up; or require "(guess)" markers like names.log reasons do.
- **Cost of not having it:** none directly; quality risk for later workers.
